# The pipeline — a detailed reference

Gate set **`2026-10-27.4`**. This file describes the pipeline as built, not as intended. If a
statement here and the code disagree, the code is right and this file is a bug.

---

## 1. What it is

A production line for one vertical shot, made of **thirteen stages** and **nine code gates**,
with seven agents that each own one artifact. The design rule is the whole point:

> **The agent that produces an artifact never grades it.**

So every stage is one of three kinds, and the kind decides who can pass it:

| kind | who runs it | can it be faked |
|---|---|---|
| **code** | `run.mjs` invokes it, reads its exit code and its findings | no — it opens the page and measures it |
| **judge** | an agent writes a signed verdict file; `run.mjs` validates the signature | only by lying in a file, and the lie is on the record |
| **user** | you, with a quote | no |

A judgement gate cannot be generated by the pipeline. `run.mjs` has no code path that writes a
`reading` or `rhythm` verdict, and `submit` refuses a verdict whose `agent` does not match the
stage's owner.

## 2. The line

```
   director      →  spec.json              what the shot is, and why every beat exists
       ↓  spec · voice
   image         →  screen.html            the drawing
       ↓  image · frame · scene · figures
   image-critic  →  reading verdict        does the picture say the sentence        [signed]
       ↓  motion
   motion-critic →  rhythm verdict         does every change mean something        [signed]
       ↓  sound
   sound         →  the mixed track        trimmed to speech, placed on the word
       ↓  still                             ← the user's word
   encode        →  the file               refuses to run without the approval
       ↓  watch                             ← the user
```

## 3. What each gate actually refuses

The rule names below are the strings the gates print. They are stable on purpose: a finding you can
grep for is a finding you can track.

### 3.1 `spec` — the spec is legal
Schema-checked against `pipeline/schema/spec.schema.json`, with `additionalProperties: false`.

| finding | raised when |
|---|---|
| `X is not a key of a shot spec — is it a typo?` | any key the schema does not declare |
| `X is missing` | a required key (`shot, format, duration, frame, lines, objects, whitelist`) |
| `X is <type>, must be <type>` | wrong type anywhere, including nested |
| `"x" is not one of …` | bad enum — `format`, `projection`, `approval.state` |
| `X does not match <pattern>` | `shot` must be `^[a-z0-9][a-z0-9-]*$`, line ids `^l\d+$` |
| `the spec calls itself "x" but lives in y/` | spec name ≠ folder name (a copy that has drifted) |
| `this is still the scaffold the pipeline generated` | `scaffold: true` |
| (plus hand-written checks) | no lines, no objects, a line with no measured `in`, an object serving a line that does not exist, no beats, a beat with no `why`, a shot that does not declare how it ends |

### 3.2 `voice` — the words, before anything is drawn
| finding | raised when |
|---|---|
| `line lN uses "leverage"` | a word from the ban list: utilise, utilize, leverage, performant, mechanism, subsequently, thus, hence, in order to, utilization |
| `line lN is N words long` | more than 16 spoken words (a *spoken* line is a sentence; the 2–3 word rule is for on-screen text) |
| `line lN says the same thing as lM` | a duplicate line, unless `loop: true` and it is the last line restating the first |
| `line lN says 128, and no entry in spec.sources carries it` | a number with no `sources[]` claim containing it, and no `sources[].numbers` entry |
| `line lN starts at Xs, before the previous line ends at Ys` | two voices in one second |
| `line lN ends at Xs, after the shot ends at Ys` | the last word lands outside the shot |

### 3.3 `image` — the page contract
| finding | raised when |
|---|---|
| `the page never sets window.__ready = true` | timeout after 15 s |
| `the page does not expose window.__boxesAt` | one of `__total, __draw, __boxesAt, __audit` is not a function |
| `the page threw: …` | any `pageerror` or console error |
| `__total() returned …` | not a positive number |
| `the page runs Xs and the spec says Ys` | the drawing and the spec disagree on length (>0.05 s) |
| `__boxesAt(t) returns boxes shaped …` | a box is not `{s,x0,y0,x1,y1}` |
| `__audit(t) returns …` | no `objects` key |
| `the page is identical at the start, the middle and the end` | a picture, not a shot |
| `object X has no legibility statement` | `reads_without_caption` missing |

### 3.4 `frame` — no text breaks the frame
Sampled every **0.1 s** across the whole shot.

| finding | raised when |
|---|---|
| `text outside the frame: "…"` | any text box crosses `l/r/t/b` from the spec's `frame` (0.5 px tolerance) |
| `a sentence, not a fragment: "…" (N words)` | more than `gates.mechanical.max_words` (default **3**) |
| `N text fragments on screen` | more than `gates.mechanical.max_texts` (default **3**) |
| `text on text: "A" over "B"` | two boxes overlap by more than 1.5 × 1.5 px |

Chrome strings in `gates.mechanical.chrome` are exempt from the word and count rules.

### 3.5 `scene` — every object is allowed and serves a line
Reads `__audit(t)` — what the page says it drew — not the pixels. Sampled every 0.1 s.

| finding | raised when |
|---|---|
| `NOT IN THE BRIEF` | a drawn `data-name` is not in the spec's `whitelist` |
| `OBJECT SERVES NO LINE` | no `data-serves` |
| `SERVES A LINE THAT DOES NOT EXIST` | `data-serves` names a line id the spec does not have |
| `OBJECTS OVERLAP` | two objects' boxes intersect by more than `overlap_max_px` (**60** px²) |
| `COUNT GOES BACKWARDS` | the counted object's visible count decreases |
| `COUNT JUMPS` | it rises by more than `count.max_jump` between two samples |
| `COUNT NEVER REACHES ITS TARGET` | final visible count < `count.target` — the count must be *counted*, not tiled |
| `TOO MANY TEXT FRAGMENTS` | mirrors the frame gate's limit |
| `TEXT OUTSIDE THE FRAME MARGIN` | mirrors the frame gate's box |

### 3.6 `figures` — every number in the voice is on the sheet
The gate that was written because two of the worst bugs on this project were caught by a person
reading stills. It parses every number out of every `lines[].text`.

Parsing handles: digits, decimals, hyphenated words, word-numbers,
`"a hundred and twenty-eight" → 128`, `"one point two" → 1.2`, `"a hundred and twenty" → 120`.
Single digits are ignored unless they are part of a bigger number, so the idiom *"one box"* does not
create a figure nobody can put on screen.

A number is **carried** if any of these is true while the line is said (±0.2 s):

1. a figure with that value is in the on-screen text,
2. it is the target of `spec.count` and the count reaches it,
3. **the count sweeps through it** — a counter is a figure that moves, so it carries every value it
   stands on, not only its target (the report prints the range, e.g. `count passes it (111–121)`),
4. it is waived in `spec.figure_waivers[]` with `{line, number, why}`.

| finding |
|---|
| `line lN says 42 and nothing on screen stands on 42 while it is said` |

### 3.7 `motion` — the move is clean
Samples every 0.1 s and compares coarse luminance grids.

| finding | raised when |
|---|---|
| `CAMERA CUTS THE PICTURE` | a subject leaves the frame during a camera move — a defect anywhere |
| `UNDECLARED CAMERA MOVE` | `__cam(t).z` changes and the move is not in `gates.motion.zoom` |
| `CAMERA MOVES TOO FAST` | zoom rate over **0.35**/s |
| `CAMERA HUNTS` | more than **0** zoom direction reversals |
| `DEAD HOLD` | no change for longer than `gates.rhythm.holds_max` (default 1.2 s) |
| `POP — the frame jumps` | more than **0.08** of the frame changes in one 0.1 s step and it is not a declared cut |

### 3.8 `sound` — levels and sync
| finding | raised when |
|---|---|
| `mean level X dB is outside −24…−12` | phone-hostile level |
| `peak X dB is over −1 dBFS` | no headroom |
| `silent tail from Xs to the end` | the piece reads as having ended early |
| `line lN starts at Xs, Ys before the speech does` | the voice is not where the spec says (0.15 s tolerance; `silencedetect` is ±0.1 s) |

### 3.9 `encode` — the file survives encoding
Renders frame by frame through `gates/render.mjs` (30 fps, crf 18, yuv420p), muxes the track to AAC
192k, then probes the output. Refuses if the render fails, the mux fails, or the encoded resolution
is not `frame.w × frame.h`.

## 4. The four guarantees

**1. Order is enforced.** A stage cannot run while any earlier stage is open. Code gates are refused
past an open judgement gate; `run <stage>` and `all` both stop rather than skip.

**2. A pass expires.** Every entry in `ledger.json` records `gateVersion`, `specHash` and `srcHash`.
`staleReason()` invalidates a pass when:

- the gate version changed (`↺ the gate has changed since this passed`),
- the spec changed (`↺ the spec changed since this passed`),
- the drawing changed (`↺ the drawing changed since this passed`),
- except that `spec` is exempt from the version rule and `spec`/`image` are exempt from the drawing rule.

A stricter gate therefore invalidates every pass earned under the old one. That is deliberate: a pass
is only a pass for the picture it was earned on, under the gate that granted it.

**3. Judgement cannot be self-generated.** A verdict file is:

```json
{ "stage": "reading", "agent": "image-critic", "verdict": "PASS",
  "summary": "…", "findings": [] }
```

`submit` refuses it if the stage is code, if the verdict is for another stage, if `verdict` is not
`PASS`/`REJECT`, if `agent` ≠ the stage owner, or if any earlier stage is still open.

**4. The gates are tested.** `node pipeline/run.mjs test` runs `pipeline/tests/run-tests.mjs`:
**16 cases**, each a fixture page or a fixture spec that breaks exactly one rule, plus the gate that
must catch it. `all` runs the suite first and **refuses to start** if a gate has stopped catching its
own case.

| # | case | proves |
|---|---|---|
| 1 | number parser, 8 sentences | word/word-hyphen/decimal/idiom parsing |
| 2 | schema, 6 malformed specs | typo, missing block, missing projection, bad enum, missing `in`, waiver without reason |
| 3 | spec name ≠ folder | copies are caught when they drift |
| 4 | text outside the box | frame gate |
| 5 | a sentence where a fragment belongs | frame gate |
| 6 | text on text | frame gate |
| 7 | a clean frame passes | no false positives |
| 8 | spoken number not on screen | figures gate |
| 9–10 | number inside / outside the count's sweep | the counter rule, both ways |
| 11 | page missing a hook | contract gate names it instead of crashing |
| 12 | page length ≠ spec | contract gate |
| 13 | voice: 4 bad cases | banned word, unsourced number, duplicate line, overlapping voices |
| 14 | voice: sourced number + declared loop | no false positives |
| 15 | count never reaches target | scene gate |
| 16 | dead hold | motion gate |

## 5. Commands

```
node pipeline/run.mjs new      <shotDir>                 start a shot
node pipeline/run.mjs status   <shotDir>                 every stage, owner, staleness reason
node pipeline/run.mjs next     <shotDir>                 the open stage, tab-separated
node pipeline/run.mjs all      <shotDir>                 every code gate in order
node pipeline/run.mjs run      <shotDir> <stage>         one code gate
node pipeline/run.mjs submit   <shotDir> <stage> <file>  one judgement gate
node pipeline/run.mjs approve  <shotDir> still "<quote>" the user's gate
node pipeline/run.mjs override <shotDir> <stage> "<why>" pass over a gate, on the record
node pipeline/run.mjs reject   <shotDir> <stage> "<why>" send work back
node pipeline/run.mjs test                               the gates' own tests
node pipeline/run.mjs doctor   [<shotDir>]               machine + shot preflight
node pipeline/run.mjs board                              all shots, one page
```

`reject` deletes every stage state from that gate onward and records the rejection. `override` logs a
waiver without deleting the failure, so the board still shows what was passed over and why.

## 6. The two inputs

### 6.1 The spec — `shorts/<shot>/<shot>.spec.json`
Authoritative schema: `pipeline/schema/spec.schema.json`.

| key | what it carries |
|---|---|
| `shot` | must equal the folder name |
| `format` | `vertical` |
| `duration` | seconds, measured off the track, not estimated |
| `src` | the drawing, relative to the repo root |
| `frame` | `{w, h, margin:{l,r,t}, safe_b}` — **nothing is drawn below `safe_b`** |
| `sound` | `{track, target_lufs}` |
| `lines[]` | `{v, text, file, trim:[a,b], in}` — `text` is what the figures gate parses |
| `objects[]` | `{name, projection, count, serves[], reads_without_caption}` — one projection per object |
| `whitelist[]` | every `data-name` allowed to be drawn |
| `count` | `{object, from, to, target, max_jump}` |
| `beats[]` | `{t, what, why}` — no beat, no animation; the last one must say how the shot ends |
| `gates` | `mechanical{max_texts,max_words,chrome}`, `semantic`, `rhythm{holds_max,…}`, `motion{cuts,zoom}` |
| `waivers[]` | `{gate, what, why≥20 chars}` |
| `figure_waivers[]` | `{line, number, why≥20 chars}` |
| `sources[]` | `{claim, url, numbers[], derivation}` — **no source, no claim** |
| `loop` | built to loop ⇒ the last line may restate the first |
| `scaffold` | `true` while it is still the generated skeleton |
| `approval` | `{still, approved_by, quote, date, state}` |

### 6.2 The page — `pipeline/PAGE.md`
A shot is a **function of time**, not an animation. Six hooks on `window`:

| hook | returns |
|---|---|
| `__ready` | `true` once fonts are loaded |
| `__total()` | the shot length in seconds |
| `__draw(t)` | the page's state at `t` — **stateless** |
| `__boxesAt(t)` | `[{s,x0,y0,x1,y1}]` for every visible text box |
| `__audit(t)` | `{objects:[{name,parent,serves,x0,y0,x1,y1}], texts, textBoxes, whitelist}` |
| `__cam(t)` | optional `{view, z, xc}` |

Plus three drawing rules: every drawn thing carries `data-name` / `data-parent` / `data-serves`;
visibility is `opacity` (effective, walked up the tree, dead below 0.06); text is `text` elements.

`new` writes a page that already satisfies all of this.

## 7. Artifacts

```
shorts/<shot>/
  <shot>.spec.json      the spec
  screen.html           the drawing
  audio/                voice files + track.wav
  verdicts/<stage>.json signed judgement, if any
  ledger.json           what passed, under which gate version, on which hashes
  reports/<stage>.txt   the gate's own words
  evidence/l-<v>.png    one full-size frame per line (plus a .thumb.jpg for the html)
  report.html           the board, with the evidence embedded so it opens anywhere
  <shot>.mp4            the encoded file
pipeline/report.html    every shot, every gate, one page
```

`report.html` for a shot contains: the gate table (state, owner, findings, fix, staleness reason), one
frame per line taken at the **middle** of that line, the spec's waivers, and every override with its
reason — then the next open gate.

## 8. Adding a gate

1. Write `pipeline/gates/<name>.mjs` exporting `run<Name>Gate(spec)` that returns
   `verdict(stage, findings, report)` — `{ok, findings, report}` with findings from `F(gate, what, fix, extra)`.
2. Read the frame, margins and limits from the **spec**, never from constants in the gate.
3. Insert the stage in `pipeline/lib/ladder.mjs` at the right point in the order, with an `owner`
   and `kind`.
4. Add a fixture that breaks the rule and a case to `pipeline/tests/run-tests.mjs`. If the gate cannot
   be made to fail on purpose, it is not a gate.
5. Bump `GATE_VERSION`. Every pass earned under the old gate goes stale, visibly.

## 10. What no gate covers

- **Taste.** The gates enforce the constraints you set — margins, fragments, no subtitles, no invented
  objects, counted counts, sourced numbers, changes with reasons. They do not say whether a shot is
  beautiful. That is `reading`, `rhythm` and `watch`, and they need judgement.
- **Meaning.** `figures` can prove the number is on screen; only `reading` can say whether the picture
  asserts what the sentence asserts.
- **Retention.** Nothing here predicts whether a stranger keeps watching. That is a research problem,
  not a gate.
- **Non-DOM drawings.** Every gate assumes an SVG/DOM page answering the six hooks. A page drawn some
  other way has to grow the hooks before it can be measured.
